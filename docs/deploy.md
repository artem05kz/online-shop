# Выкладка в интернет

Магазин целиком запускается одной командой `docker compose up -d --build`, одинаково на своём
компьютере и на сервере. Выкладка сводится к трём шагам: арендовать сервер, скопировать на него
проект и файл `.env`, выполнить ту же команду.

## Что запускается

| Контейнер | Что делает |
|-----------|------------|
| `db` | PostgreSQL 17, база магазина. Данные в томе `db-data`. |
| `app` | сам сайт (образ из `Dockerfile`). Фото в томе `media`, временные выгрузки 1С в `app-data`. Наружу не открыт. |
| `caddy` | принимает запросы снаружи (порты 80 и 443) и передаёт сайту. С доменом сам получает и продлевает сертификат HTTPS. |
| `backup` | каждую ночь зашифрованная копия базы и фото в папку `backups/` рядом с проектом, хранит 14 дней. |

Корзины, избранное и ключи входа хранятся в базе, поэтому перезапуск и обновление сайта
не выкидывают покупателей из аккаунта и не очищают их корзины.

## Запуск на своём компьютере

Нужен запущенный Docker Desktop.

1. Скопировать `.env.example` в `.env` и вписать пароль базы `POSTGRES_PASSWORD` и пароль копий
   `BACKUP_PASSWORD` (оба любые длинные). Если порт 80 занят, поставить `HTTP_PORT=8088`.
2. Запустить:

   ```bash
   docker compose up -d --build
   ```

3. Открыть `http://localhost` (или `http://localhost:8088`). Проверка, что сайт видит базу: `/health`
   отвечает `ok`.

Остановить: `docker compose stop`. Удалить контейнеры, оставив данные: `docker compose down`.
Команда `docker compose down -v` удаляет и тома, то есть базу и фото: её не использовать.

### Первый менеджер

Консольные команды сайта выполняются отдельным запуском того же образа:

```bash
docker compose run --rm app --make-manager <логин>
```

### Перенос текущей базы SQLite

База на компьютере разработчика (`src/OnlineShop.Web/App_Data/shop.db`) переносится в PostgreSQL
с прежними номерами товаров и заказов, ярлыками и датами. Перенос делается только в пустую базу,
то есть сразу после первого запуска:

```bash
docker compose run --rm --no-deps -v "<полный путь к shop.db>:/import/shop.db:ro" app --copy-from-sqlite /import/shop.db
docker compose cp src/OnlineShop.Web/media/. app:/data/media
docker compose exec -u root app chown -R app:app /data/media
docker compose restart app
```

Команда работает с копией файла и сама доводит её до текущей схемы, исходный `shop.db` не меняется.

## Что нужно от хостинга

- Сервер (VPS) с Ubuntu 22.04 или 24.04, 2 ГБ памяти, от 20 ГБ диска. Подойдёт и ARM.
- Установленный Docker (`curl -fsSL https://get.docker.com | sh`).
- Открытые порты 80 и 443.
- Домен, у которого запись A указывает на адрес сервера. Без домена сайт работает по IP,
  но без HTTPS.

## Выкладка

1. Скопировать проект на сервер (`git clone https://github.com/artem05kz/online-shop.git`).
2. Создать `.env` по образцу `.env.example`:

   | Имя | Что вставить |
   |-----|-------------|
   | `POSTGRES_PASSWORD` | новый длинный пароль базы |
   | `BACKUP_PASSWORD` | пароль шифрования копий; сохранить ещё и в менеджере паролей |
   | `SITE_ADDRESS` | домен, например `grass-aktau.kz` |
   | `HTTP_PORT`, `HTTPS_PORT` | `80` и `443` |
   | `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
   | `TWOGIS_API_KEY` | ключ 2ГИС, если есть |

3. `docker compose up -d --build`. Caddy получит сертификат за минуту, сайт откроется по `https://`.
4. Перенести данные (см. выше): скопировать на сервер `shop.db` и папку `media`
   (`scp`), выполнить те же команды.
5. Проверить: `https://<домен>/health` отвечает `ok`, вход менеджера, оформление пробного заказа
   и уведомление в Telegram, загрузка фото в панели.

Один токен бота нельзя использовать в двух местах сразу: если на компьютере запущен сайт с тем же
токеном, панель напишет «бот уже запущен в другом месте». На время работы сервера бот работает там.

## Обновление

```bash
git pull
docker compose up -d --build
```

Изменения схемы базы применяются сами при запуске. Сайт недоступен несколько секунд,
пока перезапускается контейнер.

## Резервные копии

Каждую ночь в `BACKUP_HOUR` (по умолчанию 3:00 по Актау) в папке `backups/` появляются два файла:
`shop_<дата>.dump.gpg` (база) и `media_<дата>.tar.gz.gpg` (фото без уменьшенных копий). Хранятся
`KEEP_DAYS` дней (по умолчанию 14).

Копии зашифрованы паролем `BACKUP_PASSWORD` (AES-256, формат GnuPG): в них телефоны и адреса
покупателей. Шифрование идёт на лету, незашифрованный файл на диск не попадает. Без пароля копии
не делаются вовсе. **Пароль хранить не только в `.env` на сервере**: если сервер пропадёт вместе с ним,
копии не открыть. Открыть копию на своём компьютере (gpg есть в Git Bash), например фото:

```bash
gpg --decrypt media_2026-10-07_0300.tar.gz.gpg > media.tar.gz
```

```bash
docker compose run --rm backup list        # какие копии есть
docker compose run --rm backup now         # сделать копию сейчас
```

Копии лежат на том же сервере, поэтому от поломки самого сервера не спасают. Раз в неделю их стоит
скачивать к себе: `scp -r <сервер>:online-shop/backups ./`.

### Восстановление

Заменяет текущие базу и фото содержимым копии:

```bash
docker compose stop app
docker compose run --rm backup restore 2026-10-07_0300
docker compose start app
```

Проверено 07.10.2026 на зашифрованной копии: порча базы (удалены записи о фото, переименованы товары)
и лишний файл в фото, восстановление; после него все 30 товаров и 30 фото на месте, лишнего файла нет.
С неверным паролем восстановление отказывает и ничего не трогает.

## Что стоит знать

- Ключи входа лежат в базе незашифрованными, о чём сайт предупреждает в журнале при запуске
  (`No XML encryptor configured`). Кто получил доступ к базе, и так получил всё, поэтому отдельное
  шифрование ключей не добавлено.
- Журнал сайта: `docker compose logs app --tail 100`.
- Тесты можно прогнать и на PostgreSQL, как на сервере: поднять PostgreSQL в Docker и задать
  переменную `SHOP_TEST_POSTGRES` (см. README, раздел «Тесты»).
