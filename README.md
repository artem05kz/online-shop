# Интернет-магазин GRASS Актау

Интернет-магазин автохимии и бытовой химии GRASS и Ifoam: каталог с поиском и фильтрами,
корзина, оформление заказа с оплатой при получении, личный кабинет с адресами доставки на карте
и панель управления для менеджера с загрузкой товаров, цен и остатков из 1С.

Стек: .NET 10, ASP.NET Core MVC и Razor Pages, EF Core, SQLite для разработки и PostgreSQL на сервере,
ASP.NET Core Identity, ClosedXML, Docker. Выкладка в интернет: [docs/deploy.md](docs/deploy.md).
Первая версия была на Django, история переноса и все отличия описаны в
[docs/rewrite-plan.md](docs/rewrite-plan.md).

## Запуск

Нужен .NET 10 SDK.

```bash
dotnet run --project src/OnlineShop.Web --urls http://localhost:5080
```

Сайт откроется на http://localhost:5080. База SQLite создаётся сама при первом запуске
в `src/OnlineShop.Web/App_Data/shop.db`, фото товаров и баннеров лежат в `src/OnlineShop.Web/media`.
Обе папки в репозиторий не попадают.

Выдуманный каталог, чтобы посмотреть витрину без выгрузки из 1С (только в пустую базу):

```bash
dotnet run --project src/OnlineShop.Web -- --seed-demo
```

## Панель управления

Панель открывается по адресу `/admin` и доступна только менеджерам. Первого менеджера назначают
из консоли: зарегистрируйтесь на сайте, затем выполните

```bash
dotnet run --project src/OnlineShop.Web -- --make-manager <логин>
```

и войдите заново. Дальше менеджеры выдают доступ друг другу в разделе «Покупатели и доступ».

Фото товаров и баннеров сжимаются при загрузке: фото до 2000 точек по длинной стороне, баннер
до 3840 по ширине, в формате WebP, с поворотом по метке EXIF. Принимаются файлы до 20 МБ (фото)
и 25 МБ (баннер).

Баннер на главной везде одной пропорции 3:1, на телефоне он просто меньше, поэтому надпись
на картинке не съезжает и не обрезается. Размер картинки 3840 × 1280, не меньше 1920 × 640.
Браузер сам берёт копию по ширине экрана: 960, 1280, 1920, 2560 точек или исходник. В форме
баннера видно превью с рамкой, внутри которой надпись не закроют стрелки и точки карусели,
а после сохранения панель предупреждает, если картинка обрежется или будет нечёткой.

## Загрузка из 1С

Менеджер выгружает из 1С два отчёта в Excel: прайс-лист (названия, описания, фото, фасовки,
оптовые цены) и остатки на складе. Загрузить их можно в панели («Загрузить товары»,
«Обновить остаток») с предпросмотром перед записью или из консоли:

```bash
dotnet run --project src/OnlineShop.Web -- --import-1c --price-list "прайс лист.xlsx" --stock "остатки.xlsx" --dry-run
```

С `--dry-run` файлы только разбираются и ничего не пишется в базу, без него загружаются.
Из 1С приходит оптовая цена, розничную менеджер ставит в разделе «Цены и остатки».
Выгрузки с ценами в репозиторий не кладутся: `*.xlsx` в `.gitignore`.

## Уведомления в Telegram

О каждом новом заказе бот пишет в Telegram: состав, сумма, телефон и адрес покупателя, ссылка
на заказ в панели. Бот работает внутри сайта и сам забирает сообщения у Telegram (long polling),
поэтому отдельный сервер и публичный адрес ему не нужны.

1. Создать бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопировать токен.
2. Задать токен параметром `Telegram:BotToken` (см. «Настройки») и перезапустить сайт.
3. В панели, раздел «Уведомления в Telegram», добавить номера телефонов, на которые слать заказы.
4. С каждого телефона открыть бота, нажать «Старт» и кнопку «Отправить мой номер».

Telegram не даёт боту писать человеку по одному номеру телефона: сначала человек сам должен
написать боту. Поэтому номер подключается кнопкой «Отправить мой номер», а бот принимает
только свой номер человека, не чужой контакт. Отключить уведомления можно командой `/stop` в боте
или удалением номера в панели.

## Почта покупателя

Почта обязательна при регистрации и подтверждается шестизначным кодом из письма. Без подтверждённой
почты заказ не оформить: на неё приходят письма «заказ принят» и о каждом новом статусе
(подтверждён, доставляется, выполнен, отменён), а при забытом пароле код для его смены
(«Забыли пароль?» на странице входа). Покупатели, зарегистрированные раньше, указывают почту
при следующем заказе. Неверные коды смены пароля считаются как неверные пароли: после пяти
аккаунт закрыт на 15 минут.

Проверить письма на своём компьютере без настоящего ящика: запустить Mailpit и указать его сайту.

```bash
docker run -d --name shop-mailpit -p 8025:8025 -p 1025:1025 axllent/mailpit
```

Затем `Email__Host=localhost`, `Email__Port=1025`, письма видны на http://localhost:8025.

## Настройки

| Параметр | Что задаёт | По умолчанию |
|----------|------------|--------------|
| `Database:Provider` | `Sqlite` или `Postgres` | `Sqlite` |
| `ConnectionStrings:Shop` | файл базы SQLite или строка подключения PostgreSQL | `App_Data/shop.db` |
| `Storage:AppData` | папка временных выгрузок 1С (с PostgreSQL; у SQLite рядом с базой) | `App_Data` |
| `Media:Root` | папка загруженных фото | `media` |
| `TWOGIS_API_KEY` | ключ 2ГИС: карта и поиск адреса по точке в форме адреса, карта магазинов | не задан, тогда OpenStreetMap |
| `Telegram:BotToken` | токен бота для уведомлений о заказах | не задан, тогда бот выключен |
| `Email:Host`, `Email:Port`, `Email:User`, `Email:Password` | почтовый сервер (SMTP) для кодов и писем о заказах | не задан, тогда письма ложатся файлами в `App_Data/mail` |
| `Email:From` | от кого письма | `GRASS Актау <Grassaktau@mail.ru>` |

Параметры задаются в `appsettings.json` или переменными окружения
(`Database__Provider`, `ConnectionStrings__Shop`, `Media__Root`, `TWOGIS_API_KEY`, `Telegram__BotToken`).
В Docker их задаёт `docker-compose.yml` из файла `.env`, см. [docs/deploy.md](docs/deploy.md).
Токен бота на своей машине удобнее хранить вне репозитория в user-secrets:
`dotnet user-secrets set Telegram:BotToken "<токен>" --project src/OnlineShop.Web`. Ключ 2ГИС создаётся в
[кабинете разработчика 2ГИС](https://platform.2gis.ru): бесплатный демо-ключ действует месяц,
дальше нужна подписка. Ссылки «Маршрут в 2ГИС» у адресов магазинов работают и без ключа.

## Структура

```
src/OnlineShop.Web/
  Models/            товары, фасовки, заказы, адреса, баннеры, магазины, контакты
  Data/              контекст EF Core, миграции, демо-данные
  Controllers/, Views/   витрина, корзина, оформление и история заказов (MVC)
  Pages/Accounts/    вход, регистрация, профиль, адреса доставки (Razor Pages)
  Pages/Admin/       панель управления
  Services/Import/   разбор выгрузок 1С и запись в базу
  Cli.cs             консольные команды
tests/OnlineShop.Tests/  тесты моделей, базы, каталога, страниц, панели и импорта
docs/rewrite-plan.md     перенос с Django: список функций, решения и отличия
```

## Тесты

```bash
dotnet test OnlineShop.sln
```

Тесты работают на настоящей SQLite и поднимают приложение целиком. Файлы в формате
отчётов 1С для тестов импорта собираются прямо в тестах.

Те же тесты на PostgreSQL, как на сервере: поднять базу в Docker и указать её в переменной
`SHOP_TEST_POSTGRES`. Каждый набор тестов создаёт на сервере свою базу и удаляет её после себя.

```bash
docker run -d --name shop-test-pg -e POSTGRES_USER=shop -e POSTGRES_PASSWORD=shop-dev -p 55432:5432 postgres:17
SHOP_TEST_POSTGRES="Host=localhost;Port=55432;Username=shop;Password=shop-dev" dotnet test OnlineShop.sln
```
